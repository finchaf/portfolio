# ADR-0002: Статическая сборка Next.js, отдаёт Caddy

- **Статус:** принят
- **Дата:** 2026-10-30

> Как сайт работает на сервере: готовыми файлами, без своего процесса. Читать перед тем, как
> добавить что-то, что требует сервера, и перед сменой хостинга.

## Контекст

Сайт живёт на общем сервере ([инфраструктура](../infrastructure.md)) рядом с другим продуктом: его
базой, API, сайтом и расписанием. Ресурсы не ограничение: 30.10.2026 занято 753 МБ из 1 895, на диске
свободно 33 ГБ. Поэтому решение принималось по качеству, а не ради экономии памяти.

Сайту нужны богатая анимация, интерактив и 3D, два языка, хороший поиск и мгновенный ответ. Всё это
работает в браузере. Серверных данных, форм и входа на сайте нет: контакт — Telegram и почта.
Репозиторий будет открыт ([ADR-0008](0008-open-repository.md)).

## Варианты

**A. Next.js `output: "export"`, файлы отдаёт Caddy.** Ответ не тратит время на приложение. Нет
процесса, который падает, течёт или получает уязвимость. Выкатка атомарна, откат мгновенный. Папку
можно перенести на любой хостинг. Цена: нет оптимизатора картинок на лету, `proxy.ts` и заголовков из
`next.config`; они переезжают в сборку и в Caddy.

**B. Next.js `output: "standalone"` в контейнере, как сайт продукта.** Точная копия знакомой схемы.
Цена: образ, реестр, Trivy, healthcheck, предел памяти и контейнер с Node рядом с базой чужого
продукта. Обновления безопасности Next.js и React становятся срочными. Возможности сервера при этом
не используются. Для сайта с данными API и ISR эта схема верна, для этого сайта она лишняя.

**C. Внешний статический хостинг** (Vercel, Pages). Удобно, но ADR-0001 бэкенда отсекает зарубежные
CDN для российских читателей: операторы режут соединения с Cloudflare.

## Решение

Выбран **вариант A**: он лучше не потому, что дешевле, а потому что быстрее, надёжнее и безопаснее для
соседа по серверу и даёт то же самое в браузере. Анимации ничего не теряют: они полностью клиентские.

Проверено прототипом 30.10.2026 на Next.js 16.4.3 и Caddy 2.11.4, в Chrome, с действующей CSP:

| Что | Результат |
| --- | --- |
| `[locale]`, `next-intl`, `next/root-params`, `generateStaticParams` | `/ru.html`, `/en.html`, страницы работ |
| `experimental.globalNotFound` | `404.html`, ответ `404` с `noindex` |
| Выбор языка в Caddy | `ru` или нет заголовка → `/ru`, остальное → `/en`, `302`, `Vary` |
| Переходы `<ViewTransition>` на обычном `<Link>` | `document.startViewTransition` вызван, навигация без перезагрузки |
| Motion, GSAP с закреплением и SplitText, Lenis, three.js | Работают, нарушений CSP нет |
| Сжатие заранее, `precompressed` | `Content-Encoding: gzip` с диска |
| Кэш | `immutable` у `/_next/static/*`, `must-revalidate` у HTML |
| Диапазоны для видео | `206` |

Что куда переехало:

| Было бы в Next.js | Где теперь |
| --- | --- |
| `proxy.ts`, выбор языка | Caddy: правило то же, что в вебе продукта |
| `headers()`, CSP | Caddy |
| `next/image` на лету | Сборка медиа ([документ](../../03-data/media.md)) |
| Сжатие | Сборка: файлы `.br` и `.gz` рядом с оригиналами |

## Последствия

**Хорошее:** нулевая цена ответа, нет простоя при выкатке, портативность, ничего секретного при сборке.

**Плохое:**

- Правка заголовков — это правка `Caddyfile` в репозитории бэкенда и перезапуск Caddy. CSP поэтому с
  самого начала достаточно широка для WebGL, WASM и воркеров.
- Нельзя выдать ответ, зависящий от запроса. Закрытый кейс делается `basic_auth` в Caddy.
- Страница 404 одна на оба языка.

**Обратимо:** сменить `output` на `standalone` и добавить контейнер — вечер работы, код страниц при
этом не меняется.

**Триггер пересмотра:** функция, которой нужен сервер, например живые данные на каждый запрос или
чат с ИИ. Сначала проверяется отдельный маленький сервис; весь сайт на Node переводится, только если
этого мало.
