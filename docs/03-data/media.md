# Медиа

**Статус:** спецификация — проверяется на первом настоящем видео

> Как картинки и видео попадают на сайт. Открывать перед добавлением медиа.

`next/image` на лету в статической сборке нет ([ADR-0002](../01-architecture/decisions/0002-static-export-on-caddy.md)):
`images.unoptimized` стоит один раз в `next.config.ts`, и картинке не нужно повторять его. Сборка
заранее даёт результат не хуже: современные форматы при максимальном сжатии, а время сервера не
тратится.

## Путь файла

1. Исходник лежит в `media/` под Git LFS. Бесплатная квота GitHub — 10 ГиБ хранения и 10 ГиБ трафика в
   месяц, старые страницы справки говорят об 1 ГБ: сверить при настройке.
2. `scripts/build-media.ts` создаёт варианты в `public/media/`, имя содержит хеш содержимого.
3. Результат сборки в git не попадает. В git лежит манифест `src/media.generated.json`: размеры,
   цвет-заглушка, адреса. Поэтому CI работает без LFS, а сайт не прыгает при загрузке.
4. Компоненты `<Picture>` и `<Video>` читают манифест.

| Тип | Что получается |
| --- | --- |
| Картинка | AVIF и WebP на нескольких ширинах, JPEG как запасной |
| Видео | MP4 H.264 для совместимости, AV1 или VP9 для веса, постер в AVIF |

Кэш `public/media` — по хешу: файл пересобирается, только если изменился исходник.

## Правила

- **Первый экран:** один приоритетный файл, остальное лениво.
- **Видео:** короткие петли, без звука, `playsinline`, не длиннее 15 секунд и не больше 8 МБ.
- **За пределами экрана** видео стоит на паузе, при `prefers-reduced-motion` показывается постер.
- **Размеры известны заранее**, поэтому страница не прыгает.
- **В кадре нет настоящих данных людей и приватного содержимого.**
- **Шрифты и медиа — только с понятными правами**: репозиторий будет открыт.

## Дополнение 06.11.2026: AVIF

Страница импортирует AVIF, а WebP рядом остаётся исходником: из него AVIF собирается заново, его читают картинки
превью (`scripts/og/cards.ts`) и резюме (`scripts/cv/cv.ts`). AVIF есть во всех наших браузерах: Chromium 111+, Safari
16.4+, Firefox 128+. Делает его `node scripts/media/avif.mjs [--screen] [--quality N] ФАЙЛ…`: снимки — качество 50 с
цветом в четверть разрешения, экраны с мелким текстом (`--screen`) — 60 с полным цветом, спрайт меню — 50 с полным.
AVIF, который не легче WebP хотя бы на 5 %, не сохраняется: тогда страница импортирует WebP. Так вышло у стен релизов
диплома, где на картинке сотни мелких страниц. Инструменты, которые пишут картинки сайта, вызывают этот скрипт сами.

Замер 06.11.2026 в Chromium, вся прокрутка `/ru` на 1440×900: снимки истории весили 1 315 КБ, стали 776; вся главная
3 079 КБ до перехода и 2 271 КБ после, первая загрузка 1 552 и 1 248 КБ (снимки, экраны глав, страницы PDF,
кадры сайта и портреты). Отличие от WebP сверено на увеличении вдвое и в Chromium и WebKit
попиксельно: цвет совпадает до 3 единиц из 255. Декодер `sharp` показывает AVIF бледнее, чем браузер: сравнивать
картинки им нельзя.

Turbopack не читает размер AVIF и даёт импорту 100 × 100: до загрузки страница держала бы под каждой картинкой квадрат
и прыгала бы, когда она придёт. Поэтому `avif.mjs` записывает настоящие размеры в `src/ui/avif-sizes.json`
(`--sizes` пересобирает его по готовым файлам), а картинки показывает `Image` из `src/ui/image.tsx`, который берёт
размер оттуда. Тест `src/ui/avif-sizes.test.ts` сверяет манифест с рамкой `ispe` каждого файла и не пускает AVIF
мимо этой обёртки.
