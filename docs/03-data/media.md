# Медиа

**Статус:** спецификация — проверяется на первом настоящем видео

> Как картинки и видео попадают на сайт. Открывать перед добавлением медиа.

`next/image` на лету в статической сборке нет ([ADR-0002](../01-architecture/decisions/0002-static-export-on-caddy.md)).
Сборка заранее даёт результат не хуже: современные форматы при максимальном сжатии, а время сервера
не тратится.

## Путь файла

1. Исходник лежит в `media/` под Git LFS. Бесплатная квота GitHub — 10 ГиБ хранения и 10 ГиБ трафика в
   месяц, старые страницы справки говорят об 1 ГБ: сверить при настройке.
2. `scripts/build-media.ts` создаёт варианты в `public/media/`, имя содержит хеш содержимого.
3. Результат сборки в git не попадает. В git лежит манифест `src/media.generated.json`: размеры,
   цвет-заглушка, адреса. Поэтому CI работает без LFS, а сайт не прыгает при загрузке.
4. Компоненты `<Picture>` и `<Video>` читают манифест.

| Тип | Что получается |
| --- | --- |
| Картинка | AVIF и WebP на нескольких ширинах, JPEG как запасной |
| Видео | MP4 H.264 для совместимости, AV1 или VP9 для веса, постер в AVIF |

Кэш `public/media` — по хешу: файл пересобирается, только если изменился исходник.

## Правила

- **Первый экран:** один приоритетный файл, остальное лениво.
- **Видео:** короткие петли, без звука, `playsinline`, не длиннее 15 секунд и не больше 8 МБ.
- **За пределами экрана** видео стоит на паузе, при `prefers-reduced-motion` показывается постер.
- **Размеры известны заранее**, поэтому страница не прыгает.
- **В кадре нет настоящих данных людей и приватного содержимого.**
- **Шрифты и медиа — только с понятными правами**: репозиторий будет открыт.
